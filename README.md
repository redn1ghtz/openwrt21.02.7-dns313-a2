# OpenWrt 21.02.7 для D-Link DNS-313 rev. A2

Готовая пользовательская прошивка **OpenWrt 21.02.7** с ядром **Linux 5.4.238** для **D-Link DNS-313 A2** с **32 МБ RAM**. Загрузка с SATA HDD, сеть Gigabit Ethernet, веб-интерфейс LuCI и SMB-сервер KSMBD проверены на реальном устройстве.

## 2. Что исправлено и проверено

- **RAM:** Device Tree исправлен с 64 на **32 МБ**; в параметры ядра добавлено `cma=0`. В журнале загрузки: `Memory: 22676K/32768K available` — около 22 МБ доступно после начального резервирования.
- **Заводской MAC:** адрес считывается из раздела NOR flash **RedBoot** по смещению `0x1d554` и передаётся драйверу Gemini Ethernet.
- **Ethernet:** устранено обращение к отсутствующему второму порту. Проверена работа основного порта на **1 Гбит/с**. Режим сетевого интерфейса переключен в режим DHCP-клиента.
- **USB:** USB-драйверы и утилиты **не включены в конфигурацию пакетов** облегчённого образа. Встроенные параметры USB самого ядра отдельно не проверялись.
- **KSMBD:** включен в сборку, исправлена зависимость от `sprint_oid`. Проверены загрузка модуля, `ksmbd.mountd`, TCP-порт 445, копирование и удаление файлов через Windows, macOS.
- **SMB-пользователи:** в образ добавлен `ksmbd-utils 3.4.5-3`, включая `ksmbd.adduser`. Имя `root` этой утилитой намеренно запрещено.
- **RNG:** доработан `urngd` (однократный запуск `-1`), добавлен ранний запуск `/lib/preinit/82_urngd_early`, изменён `/sbin/urandom_seed`. CRNG инициализируется примерно к 15-й секунде загрузки; три более ранних предупреждения `jshn` остаются.
- **Reset:** `KEY_ESC` заменён на `KEY_RESTART`; удержание **не менее 5 секунд и отпускание** вызывает штатную перезагрузку, **без сброса настроек**. Проверено на физической кнопке.
- **SATA и swap:** загрузка с HDD, корень ext4 на `/dev/sda4`, загрузочный раздел ext2 на `/dev/sda3`, swap около 128 МБ на `/dev/sda2`. Активация swap подтверждена журналом загрузки.
- **hd-idle:** `hd-idle` и `luci-app-hd-idle` включены в сборку для настройки остановки hdd при простое.
- **Заголовки загрузки:** загрузчик распознаёт подготовленный образ; исправлены заголовки на `DNS-313v2` и `1.04b08`.

**Внимание!** В отличии от предыдущих версий проекта - эта самая стабильная. Все функции работают, проверены файлы объемом > 8ГБ.

### Облегчение прошивки для 32 МБ RAM

В конфигурации пакетов **исключены**:

- USB: `kmod-usb-core`, `kmod-usb-fotg210`, `kmod-usb-storage`, USB Host, HID, Serial, USB-сеть, `libusb-1.0`, `usbutils`, `usb-modeswitch` и другие USB-компоненты.
- Маршрутизаторные службы: `dnsmasq`, `firewall`, PPP/PPPoE, отдельные пакеты Netfilter/conntrack.
- Wi-Fi-компоненты, Samba 4, NFS-сервер, CIFS-клиент и дополнительные драйверы файловых систем (Btrfs, XFS, NTFS и др.).

**Оставлены:** LuCI и `uhttpd`, SSH (`dropbear`), KSMBD и `wsdd2`, `block-mount`, `fdisk`, `e2fsprogs`, `hd-idle`, `urngd`, SATA, ext4, swap и IPv6. Для размера кода применены `-Os -pipe` и `CONFIG_USE_SSTRIP=y`.

**Конфиг ядра:** `CONFIG_USB_SUPPORT=y` остаётся включённым как общий параметр сборки. Также сохранены `CONFIG_KERNEL_DEBUG_FS`, `CONFIG_KERNEL_DEBUG_KERNEL`, `CONFIG_KERNEL_DEBUG_INFO`; все механизмы отладки не вырезались.

**Внимание:** 32 МБ RAM — серьёзное ограничение. Дополнительные фоновые службы могут увеличивать использование swap на HDD, мешать остановке диска и снижать отзывчивость. Не устанавливайте лишние пакеты без необходимости.

<a id="chapter-3"></a>
## 4. Скачивание и запись образа на HDD

Клонируйте репозиорий:

```sh
git clone https://github.com/redn1ghtz/openwrt21.02.7-dns313-a2.git
cd openwrt21.02.7-dns313-a2
```

Проверьте SHA-256:

```sh
sha256sum DNS-313-A2-OpenWrt-21.02.7-final.bin.gz
```

На компьютере с Linux подключите HDD NAS и определите **точное имя устройства**:

```sh
lsblk -o NAME,PATH,SIZE,MODEL,SERIAL,TYPE,MOUNTPOINTS
```

> **ВНИМАНИЕ!** Запись на диск уничтожает прежнюю таблицу разделов и перезаписывает начало диска. Существующие разделы и данные могут стать недоступными. Сделайте резервную копию. Убедитесь, что выбран **именно HDD DNS-313**, а не системный диск компьютера или VM. Все разделы целевого HDD должны быть размонтированы.

Из каталога с образом выполните, **заменив `/dev/sdX` на проверенное устройство целого HDD**:

```sh
set -o pipefail; gzip -dc DNS-313-A2-OpenWrt-21.02.7-final.bin.gz | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress
```

Проверьте, что команда завершилась без ошибок, затем выполните:

```sh
sync
```

Не записывайте образ на `/dev/sdX2`, `/dev/sdX3` или `/dev/sdX4`: нужен **весь диск**.

В образе предусмотрен swap-раздел `/dev/sda2`; в проверенной загрузке NAS swap активировался. Поэтому **повторное `mkswap` не является обязательным шагом**. Если swap после загрузки не работает, сначала проверьте его сигнатуру и `/etc/config/fstab`.

Безопасно отключите HDD, установите его в DNS-313, подключите Ethernet и включите питание.

## 5. Первое включение

Дождитесь загрузки NAS. Для подключения используйте SSH по сети или веб-интерфейс LuCI. Адрес устройства определите по настройкам сети и DHCP-таблице роутера; **получение адреса по DHCP зависит от фактической сетевой конфигурации**.

При необходимости установите пароль администратора:

```sh
passwd
```

Для диагностики аппаратная последовательная консоль работает на **19200 8N1** (`ttyS0`).

<a id="chapter-5"></a>
## 6. Разметка HDD

После записи полного образа:

| Раздел | Назначение | Размер |
|---|---|---|
| `/dev/sda1` | Данные, ext4 | **Отсутствует в образе**; создаётся отдельно |
| `/dev/sda2` | Swap | ~128 МБ |
| `/dev/sda3` | Загрузка, ext2 | ~16 МБ |
| `/dev/sda4` | Корень OpenWrt, ext4 | ~104 МБ |

На HDD большего объёма оставшееся место не размечено. **Не удаляйте разделы 2, 3, 4 и не форматируйте разделы 3, 4.**

### Создание раздела данных

На NAS:

```sh
fdisk /dev/sda
```

Создайте раздел номер 1 в свободной области диска **(n, p ENTER, ENTER, ENTER, ENTER, w)**. Проверьте результат:

```sh
fdisk -l /dev/sda
```

Отформатируйте **новый** раздел данных:

```sh
mkfs.ext4 /dev/sda1
```

Создайте точку монтирования:

```sh
mkdir -p /mnt/sda1
```

### Настройка автомонтирования и swap

Узнайте UUID:

```sh
block info
```

Откройте `/etc/config/fstab`:

```sh
vi /etc/config/fstab
```

Добавьте запись для раздела данных, подставив **его настоящий UUID**:

```text
config mount
        option target '/mnt/sda1'
        option uuid 'REPLACE_UUID_SDA1'
        option enabled '1'
```

Проверьте существующую запись swap; при необходимости добавьте **одну** запись с настоящим UUID:

```text
config swap
        option uuid 'UUID_РАЗДЕЛА_SDA2'
        option enabled '1'
```

Если swap-запись уже существует, **не дублируйте её**. После изменения конфигурации перезагрузите NAS:

```sh
reboot
```

Проверьте монтирование и swap:

```sh
df -h /mnt/sda1
free -h
```

Если swap не включился, проверьте `/etc/config/fstab` и сигнатуру раздела `/dev/sda2`. Команда `swapon` на компьютере, с которого записывали образ, **не включает swap на NAS**.

## 7. Настройка SMB-сервера ksmbd

В прошивку уже включены `kmod-fs-ksmbd`, `ksmbd-server`, `ksmbd-utils` и `luci-app-ksmbd`. Пользователи, пароли и общие папки **не преднастроены в чистом образе**.

После создания и монтирования `/dev/sda1` настройте **отдельного системного пользователя `smbuser`**, его группу и SMB-пароль. Это нужно, чтобы KSMBD мог сопоставить SMB-учётную запись с Linux UID/GID. В проверенной конфигурации использованы **UID 1000 и GID 1000**; если они заняты, выберите другие свободные значения и последовательно замените их во всех командах ниже.

### 1. Проверка UID и GID

На NAS проверьте, не заняты ли номера `1000`:

```sh
awk -F: '$3==1000 || $4==1000 {print FILENAME ": " $0}' /etc/passwd /etc/group
```

**Пустой вывод** означает, что совпадений в этих файлах нет. Если записи найдены, не используйте эти номера для `smbuser`.

### 2. Создание системного пользователя и группы

В **чистой прошивке**, если пользователя и группы `smbuser` ещё нет, добавьте записи:

```sh
echo 'smbuser:*:1000:1000:SMB user:/var:/bin/false' >> /etc/passwd
```

```sh
echo 'smbuser:x:1000:' >> /etc/group
```

**Не добавляйте эти строки повторно**, если пользователь или группа уже существуют. Запись `*` **блокирует вход по системному паролю** (это не пустой пароль), а `/bin/false` запрещает обычную интерактивную оболочку. Для SSH пользователь не предназначен. KSMBD использует **отдельную базу паролей**.

Проверьте учётную запись:

```sh
id smbuser
```

Ожидаемый результат: `uid=1000(smbuser) gid=1000(smbuser) groups=1000(smbuser)`.

### 3. Создание папки и назначение прав

Убедитесь, что `/mnt/sda1` действительно смонтирован с раздела данных, прежде чем создавать каталог. Затем:

```sh
mkdir -p /mnt/sda1/Data
chown -R 1000:1000 /mnt/sda1/Data
chmod 0770 /mnt/sda1/Data
ls -ld /mnt/sda1/Data
```

Ожидается владелец `smbuser smbuser` и права `drwxrwx---`. Команда `chown -R` меняет владельца **всего содержимого** папки `Data`, но не удаляет файлы. На уже используемом NAS проверьте, что внутри нет файлов других пользователей, прежде чем применять её.

**Почему не `nobody:nogroup`:** в ходе проверки SMB заработал при временном совпадении UID `smbuser` и `nobody` (`65534`), но это смешивало их права. Окончательная проверенная настройка — **отдельный UID/GID 1000** и каталог `smbuser:smbuser`.

### 4. Создание пользователя KSMBD и пароля

В прошивке используется `ksmbd-utils 3.4.5-3`. Для **нового** SMB-пользователя (замените на Ваш пароль):

```sh
ksmbd.adduser -a smbuser -p 'YOUR_PASSWD'
```

Если пользователь уже есть в базе KSMBD, **обновите** его пароль вместо повторного создания:

```sh
ksmbd.adduser -u smbuser -p 'YOUR_PASSWD'
```

**Важно:** имя `root` утилита `ksmbd.adduser` намеренно отклоняет. Интерактивный ввод пароля в этой сборке приводил к проблемам с отображением последовательной консоли и ошибкам `Passwords don't match`; вариант с `-p` успешно проверен. **Пароль в командной строке может остаться в истории оболочки**, поэтому не используйте такой способ с паролем от других важных учётных записей и не публикуйте команду с настоящим паролем.

### 5. Настройка общего ресурса

В LuCI откройте **Services → Network Shares** и задайте:

| Параметр | Значение |
|---|---|
| Interface | `lan` |
| Name | `Data` |
| Path | `/mnt/sda1/Data` |
| Read only | `No` |
| Allowed users | `smbuser` |
| Guest access | `No` |

Сохраните изменения (**Save & Apply**).

После изменения системного UID/GID или настроек KSMBD **перезапустите службу**, чтобы она перечитала данные:

```sh
/etc/init.d/ksmbd restart
```

### 6. Подключение и проверка

Windows — в проводнике:

```text
\\IP_АДРЕС_NAS\Data
```

macOS — в Finder → «Подключиться к серверу»:

```text
smb://IP_АДРЕС_NAS/Data
```

Выберите **зарегистрированного пользователя** `smbuser` и пароль KSMBD, заданный через `ksmbd.adduser`. Если клиент запомнил старые учётные данные, выберите повторный вход с новыми данными.

**Не открывайте SMB-порт TCP 445 в интернет.**

## 9. Консоль и кнопки управления

- **UART:** аппаратная последовательная консоль `ttyS0`, **19200 бод, 8N1**. Требуется подходящий последовательный адаптер с совместимыми уровнями сигналов; не подключайте RS-232 напрямую к TTL-контактам.
- **USB:** USB-консоль CDC ACM, описанная в README OpenWrt 25.12.6, **не входит в текущую облегчённую сборку**. USB-пакеты отключены.
- **Reset:** удерживайте кнопку **не менее 5 секунд**, затем отпустите — NAS выполнит штатную перезагрузку. **Это не factory reset**. Физическая проверка выполнена при удержании около 7 секунд.
- **Power:** корректное выключение системы.

<a id="chapter-9"></a>
## 10. Особенности и ограничения

- Всего **32 МБ физической RAM**; часть памяти занята ядром и резервируется при загрузке.
- Swap (~128 МБ) помогает при нехватке RAM, но существенно медленнее оперативной памяти и создаёт обращения к HDD.
- ARMv4, 300 МГц ограничивает скорость SMB и производительность дополнительных служб.
- В прошивке **нет установленных USB-драйверов и USB-утилит** по конфигурации пакетов; наличие USB-патча в исходниках не меняет этого.
- Отдельный раздел данных `/dev/sda1`, системный пользователь `smbuser`, SMB-пароль и общие папки **не включены в чистый образ**: их нужно создать по инструкции разделов 6–7.
- В раннем журнале остаются три предупреждения `random: jshn: uninitialized urandom read` до инициализации CRNG.
- Сборка ориентирована на **аппаратную ревизию A2**; работа на других ревизиях не подтверждена.
- Дорогостоящие функции отладки ядра не объявляются полностью отключёнными: `CONFIG_KERNEL_DEBUG_FS`, `CONFIG_KERNEL_DEBUG_KERNEL`, `CONFIG_KERNEL_DEBUG_INFO` включены.
- Заголовки образа успешно распознаются загрузчиком.
